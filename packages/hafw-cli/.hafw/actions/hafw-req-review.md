# HAFW 需求评审指令

## 目标

对生成的需求规范文档（PRD）进行全面评审，检查完整性、一致性、可行性，识别潜在风险。

## 输入

- PRD 文档路径
- 架构约束
- 资源限制

## 执行步骤

### 1. 完整性检查

检查 PRD 文档是否包含必要章节：

| 检查项 | 要求 | 状态 |
|--------|------|------|
| 文档信息 | 版本、日期、作者 | ⬜ |
| 需求概述 | 背景、目标、范围 | ⬜ |
| 功能需求 | 用户故事、功能列表 | ⬜ |
| 非功能需求 | 性能、安全、可用性 | ⬜ |
| 数据模型 | 实体、关系 | ⬜ |
| 接口需求 | API 定义 | ⬜ |
| 验收标准 | 可测试的验收条件 | ⬜ |
| 风险评估 | 风险识别和缓解 | ⬜ |

### 2. 一致性检查

检查文档内部一致性：
- 术语使用是否统一
- 数据模型与功能需求是否匹配
- 用户故事与功能列表是否对应
- 验收标准是否可验证

### 3. 可行性评估

评估需求的技术可行性：

| 评估维度 | 评估内容 | 风险等级 |
|---------|---------|---------|
| 技术可行性 | 现有技术栈是否支持 | 高/中/低 |
| 时间可行性 | 工期是否合理 | 高/中/低 |
| 资源可行性 | 人力/硬件资源是否充足 | 高/中/低 |
| 依赖可行性 | 外部依赖是否可控 | 高/中/低 |

### 4. 生成评审报告

```markdown

## 评审信息
| 项目 | 内容 |
|-----|------|
| PRD 文档 | {文档名称} |
| 评审日期 | {日期} |
| 评审结果 | 通过/有条件通过/不通过 |

## 完整性检查
| 检查项 | 状态 | 备注 |
|--------|------|------|
| 文档信息 | ✅/❌ | {备注} |
| 需求概述 | ✅/❌ | {备注} |
| 功能需求 | ✅/❌ | {备注} |
| 非功能需求 | ✅/❌ | {备注} |
| 数据模型 | ✅/❌ | {备注} |
| 接口需求 | ✅/❌ | {备注} |
| 验收标准 | ✅/❌ | {备注} |
| 风险评估 | ✅/❌ | {备注} |

| 序号 | 问题描述 | 严重程度 | 建议修改 | 负责人 |
|-----|---------|---------|---------|--------|
| 1 | {描述} | 高/中/低 | {建议} | {负责人} |

| 风险 | 可能性 | 影响 | 缓解措施 | 状态 |
|-----|--------|------|---------|------|
| {风险} | 高/中/低 | 高/中/低 | {措施} | 已识别 |

## 评审结论
### 通过标准
- [ ] 所有必要章节完整
- [ ] 无严重级别问题
- [ ] 中级别问题不超过 3 个
- [ ] 风险已识别并有缓解措施

### 评审意见
{评审结论和建议}

### 下一步行动
1. {行动项}
2. {行动项}
```

### 评审报告
- 文件路径：`.hafw/{项目名称}/requirements/REVIEW-{PRD-ID}.md`
