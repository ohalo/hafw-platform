# HAFW 代码审查指令

## 目标

对代码进行人工审查，检查代码质量、规范符合性、设计合理性，发现潜在问题。

## 输入

- 代码文件或 PR
- 编码规范
- 设计文档

## 执行步骤

### 1. 静态分析

使用工具进行初步检查：
```bash
# 代码规范检查
mvn checkstyle:check

# 静态分析
mvn spotbugs:check

# 安全扫描
mvn dependency-check:check
```

### 2. 人工审查检查清单

#### 2.1 代码规范
- [ ] 命名规范（类名、方法名、变量名）
- [ ] 代码格式（缩进、空格、换行）
- [ ] 注释规范（类注释、方法注释、行注释）
- [ ] 导入规范（无未使用导入）

#### 2.2 代码质量
- [ ] 方法长度适中（< 50 行）
- [ ] 类职责单一（SRP）
- [ ] 圈复杂度合理（< 10）
- [ ] 无重复代码（DRY）

#### 2.3 设计合理性
- [ ] 符合设计模式原则
- [ ] 接口设计合理
- [ ] 异常处理完善
- [ ] 日志记录恰当

#### 2.4 安全性
- [ ] 无 SQL 注入风险
- [ ] 无 XSS 风险
- [ ] 敏感信息处理正确
- [ ] 权限控制完整

#### 2.5 性能考虑
- [ ] 无 N+1 查询问题
- [ ] 循环中无数据库操作
- [ ] 大对象处理合理
- [ ] 缓存使用恰当

### 3. 生成审查报告

```markdown
# 代码审查报告

## 审查信息
| 项目 | 内容 |
|-----|------|
| 审查对象 | {文件/PR} |
| 审查日期 | {日期} |
| 审查结果 | 通过/有条件通过/不通过 |

## 审查统计
| 类别 | 通过 | 问题数 |
|-----|------|--------|
| 代码规范 | ✅/❌ | {count} |
| 代码质量 | ✅/❌ | {count} |
| 设计合理性 | ✅/❌ | {count} |
| 安全性 | ✅/❌ | {count} |
| 性能考虑 | ✅/❌ | {count} |

## 问题详情
| 位置 | 级别 | 类别 | 问题描述 | 建议修改 |
|-----|------|------|---------|---------|
| {文件}:{行号} | 高/中/低 | 规范/质量/安全 | {描述} | {建议} |

## 优秀实践
{代码中值得推广的优秀实践}

## 审查结论
{总体评价和改进建议}
```

- 文件路径：`.hafw/{项目名称}/qa/code-review-{timestamp}.md`
