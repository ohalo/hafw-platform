# HAFW 任务状态更新指令

## 目标

更新任务的执行状态、进度和备注信息。

## 用法

```bash
/hafw-task-update {任务ID} status={状态} [progress={进度}] [note={备注}]
```

## 参数说明

| 参数 | 必填 | 说明 | 可选值 |
|-----|------|------|--------|
| 任务ID | 是 | 任务唯一标识 | T{需求ID}-001 |
| status | 是 | 任务状态 | 未开始/待开发/开发中/待测试/测试中/已完成/已暂停 |
| progress | 否 | 完成进度 | 0-100 |
| note | 否 | 备注说明 | 任意文本 |
| owner | 否 | 负责人 | 用户名 |

## 状态说明

| 状态 | 图标 | 说明 |
|-----|------|------|
| 未开始 | ⬜ | 任务已创建，等待开始 |
| 待开发 | 🔄 | 等待开发人员开始 |
| 开发中 | 🔄 | 正在开发中 |
| 待测试 | 🔄 | 开发完成，等待测试 |
| 测试中 | 🔄 | 正在测试中 |
| 已完成 | ✅ | 任务已完成 |
| 已暂停 | ⏸️ | 任务已暂停 |

## 示例

### 开始开发
```bash
/hafw-task-update T001-001 status=开发中 progress=0 note="开始开发"
```

输出：
```
✅ 任务状态更新成功

任务ID: T001-001
任务名称: 数据库设计
状态: ⬜ 未开始 → 🔄 开发中
进度: 0%
更新时间: 2024-03-13 10:30:00
操作人: {username}

备注: 开始开发
```

### 更新进度
```bash
/hafw-task-update T001-001 progress=50 note="完成表结构设计"
```

输出：
```
✅ 任务进度更新成功

任务ID: T001-001
任务名称: 数据库设计
状态: 🔄 开发中
进度: 0% → 50%
更新时间: 2024-03-13 14:00:00

备注: 完成表结构设计
```

### 完成任务
```bash
/hafw-task-update T001-001 status=已完成 progress=100 note="已通过代码审查"
```

输出：
```
✅ 任务完成

任务ID: T001-001
任务名称: 数据库设计
状态: 🔄 开发中 → ✅ 已完成
进度: 100%
完成时间: 2024-03-13 16:00:00

备注: 已通过代码审查

🎉 恭喜！任务已完成

后续任务:
➡️ T001-002 实体类开发 [依赖已满足]
   状态: ⬜ 未开始 → 🔄 待开发
```

### 暂停任务
```bash
/hafw-task-update T001-002 status=已暂停 note="等待接口文档确认"
```

输出：
```
⏸️ 任务已暂停

任务ID: T001-002
任务名称: 实体类开发
状态: 🔄 待开发 → ⏸️ 已暂停
暂停时间: 2024-03-13 11:00:00

暂停原因: 等待接口文档确认

⚠️ 注意: 此任务有 {count} 个下游依赖任务将受影响
```

## 自动触发

状态变更时自动触发：

| 状态变更 | 自动操作 |
|---------|---------|
| 未开始 → 待开发 | 通知负责人 |
| 开发中 → 待测试 | 触发自动化测试 |
| 待测试 → 测试中 | 分配测试人员 |
| 已完成 | 检查下游依赖任务，更新为"待开发" |
| 已暂停 | 通知相关依赖任务负责人 |

## 批量更新

```bash
# 批量完成多个任务
/hafw-task-update T001-001,T001-002,T001-003 status=已完成

# 批量分配给同一人
/hafw-task-update T001-004,T001-005 owner=zhangsan
```
